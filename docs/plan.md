# Точка диалога: отдельный план разработки в Codex

Дата: 24 октября 2026

## 1. Цель и границы

Создать русскоязычный учебный сайт о школьной медиации для детей 7–10 лет, родителей и учителей
Это самостоятельный вариант разработки с исходным кодом, отдельный от плана сборки в конструкторе
Сохраняем спокойное оформление, наглядные материалы, пять игровых ситуаций и печатные памятки

Первая версия: обучение, практика, библиотека и страница получения помощи
Без регистрации учащихся, переписки, приёма реальных обращений и ИИ API
На странице помощи показываем только согласованные контакты службы, без вымышленных телефонов и обещаний конфиденциальности

Детская аудитория согласована: 7–10 лет, начальная школа
Для родителей и учителей делаем отдельные подборки материалов и пояснения к детским упражнениям
Архитектура предусматривает метки аудитории и возрастной группы материала, дата рождения пользователя не требуется

## 3. Стек и причины выбора

Основной вариант утверждён: React + TypeScript + Vite
Первая версия работает как статическое веб-приложение: уроки, игры, поиск и прогресс обрабатываются в браузере
Материалы обновляем через Codex и публикуем вместе с новой сборкой

| Часть | Выбор | Назначение |
| --- | --- | --- |
| Интерфейс | React + TypeScript | Страницы, компоненты, игровые состояния и типизация |
| Сборка и локальный запуск | Vite | Единый процесс разработки и сборка готовых файлов |
| Навигация | React Router | Отдельные адреса уроков, памяток и кейсов |
| Оформление | Обычный CSS с переменными | Общие цвета, размеры, адаптивность и печатная версия |
| Материалы | Отдельные JSON-файлы | Один кейс, урок или памятка в одном файле |
| Проверка материалов | Zod и проверка связей между файлами | Выявление пропущенных полей, неверных переходов и ссылок до публикации |
| Прогресс | localStorage с резервной работой в памяти | Продолжение в том же браузере |
| Проверки | Vitest, React Testing Library, Playwright | Игровая логика, значимые взаимодействия и ключевые пользовательские пути |
| История и воспроизводимость | Git, package-lock.json, зафиксированная версия Node.js | Возврат к рабочей версии и повторяемая установка |

Критерии выбора: простой запуск, понятная структура, небольшое число зависимостей и удобные изменения через Codex
Один общий игровой компонент обслуживает все пять кейсов, новый текст не требует переписывать экран
TypeScript помогает обнаруживать несогласованные типы, структуру JSON и связи дополнительно проверяем перед сборкой
Надёжность подтверждаем проверками, работоспособной сборкой и историей изменений

Для согласованных функций первой версии отдельный сервер, API и база данных не требуются
Node.js используется для инструментов разработки и сборки, опубликованному сайту отдельный процесс Node.js не нужен
Русский текст, изображения и PDF поставляются как часть сайта
Добавление или исправление материала требует новой сборки и публикации
Автономную работу без интернета в первую версию не включаем

Rust + Axum и SQLite исключены из основного плана
Rust был допустимым техническим вариантом, но добавлял второй язык, отдельный сервер, импорт в базу и дополнительные настройки
Дальнейшее развитие с кабинетом редактора описано отдельно в разделе 15

## 6. Обучение

Четыре модуля, в каждом два коротких урока и три вопроса с пояснениями

1) Кто помогает договориться? Что такое медиация и чем помогает посредник
2) Как слушать и говорить о себе? Уточняем и обходимся без обвинений
3) Что важно каждому? Учимся понимать желания и ожидания
4) Как договориться? Предлагаем варианты и решаем, что делать дальше

Формат урока: цель > короткое объяснение > схема или таблица > пример > небольшой вопрос > следующий материал
Основные понятия объясняем через школьные ситуации, без перегрузки терминами
Детская версия рассчитана на 7–10 лет: один экран содержит одну мысль, иллюстрацию и 2–4 коротких предложения
Термин "медиация" сразу объясняем понятными словами, профессиональные подробности выносим в блок для взрослых
Вместо длинной главы используем несколько коротких экранов, которые можно проходить в своём темпе
В тестах нет таймера, рейтинга детей и штрафа за ошибку, ответ можно обдумать и попробовать снова
Схемы состоят из небольшого числа подписанных шагов, текст не встраиваем в картинки
Родитель или учитель может читать материал вслух, самостоятельное чтение не делаем единственным способом пройти занятие
Автоматическая озвучка в первую версию не входит
Материалы до использования в реальном обучении проверяет преподаватель или куратор
Разделяем обычные разногласия и ситуации угроз, насилия или травли, где требуется помощь ответственного взрослого и меры защиты
Не предлагаем ребёнку самостоятельно примирять участников опасной ситуации

## 7. Пять игровых кейсов

| Название | Участники | Для кого | Навык |
| --- | --- | --- | --- |
| Общее задание | Два ученика делают общий плакат | Дети 7–10 лет, совместный разбор с учителем | Спросить, кто что сделает, и разделить работу |
| Игра на перемене | Ученики выбирают игру и распределяют роли | Дети 7–10 лет | Выслушать разные пожелания и предложить очередность |
| Сначала уроки или отдых? | Ребёнок и родитель | Дети со взрослым, родители | Рассказать об усталости и обсудить понятный порядок действий |
| Меня не услышали | Ученик и учитель | Дети, совместный разбор с учителем | Попросить объяснить задание и спокойно рассказать о затруднении |
| Разные ожидания | Родитель и учитель | Родители и учителя | Обсудить нагрузку через факты и вопросы |

Кейс про классный чат заменяем игрой на перемене, чтобы детская практика не требовала опыта пользования мессенджером
В детских кейсах пользователь выбирает действия своего персонажа, ребёнок не отвечает за поведение взрослых
Во взрослом семейном разборе дополнительно объясняем, как родитель может выслушать ребёнка

Каждый кейс: вводная иллюстрация, четыре сюжетных шага, по три варианта ответа, пояснение после каждого выбора и итог
На детском шаге показываем один короткий вопрос и три короткие реплики, пояснение ограничиваем 1–2 простыми предложениями
Итог для ребёнка содержит понятный вывод и один приём, который можно попробовать, подробный разбор доступен взрослому отдельно
Выбор влияет на ближайшую реплику и итоговый разбор
Затем ветви сходятся к следующему общему шагу, чтобы объём оставался управляемым
Это ограниченное ветвление с последствиями, не свободный разговор с ИИ
В данных явно храним next_step_id и проверяем все переходы

Пример для кейса об общем задании

Ситуация: Маша и Саша делают плакат для класса, Маша уже нарисовала рисунок и сердится, а Саша не знает, чем помочь

| Выбор | Возможное продолжение | Учебное пояснение |
| --- | --- | --- |
| "Ты совсем не помогаешь!" | Саша отвечает: "Ты сама всё взяла!" | От таких слов можно ещё сильнее поссориться |
| "Ладно, я всё сделаю сама" | Маша продолжает одна и устает | Маша не сказала, какая помощь ей нужна |
| "Я нарисую, а ты вырежешь буквы?" | Саша предлагает начать с букв | Так понятно, кто что будет делать, можно обсудить и другой вариант |

Это вымышленный учебный пример, не гарантия поведения реальных людей
Не ставим оценки личности и не обещаем, что одна фраза всегда решает конфликт
Предусматриваем повтор, выход и возврат к началу
Автоматически не переходим дальше до прочтения пояснения

## 8. Памятки и печать

Восемь первоначальных материалов

1) Сделай паузу перед ответом
2) Скажи о себе без обвинения
3) Как выслушать и уточнить
4) Как обсудить общее задание
5) Как договориться об игре на перемене
6) Как поддержать ребёнка после ссоры
7) Как начать обсуждение разногласия в классе
8) Как подготовиться к разговору родителя и учителя

Каждая памятка: аудитория, короткая цель, 4–6 действий, схема или таблица, пример реплики и чеклист
Первые пять памяток делаем для детей 7–10 лет, остальные три для родителей и учителей
В детской памятке 4 коротких действия с картинками и один пример, в версии для взрослых допускается более подробная таблица
В детских примерах используем знакомые ситуации: общий рисунок, игра, очередь и разговор о задании
Иллюстрации в одном стиле, русский текст накладываем средствами верстки для читаемости
Первый вариант печати реализуем через отдельный печатный стиль и системный диалог браузера
Дополнительно готовим отдельные PDF A4, кнопка скачивания указывает на реальный проверенный файл
Для PDF используем подходящий навык подготовки документов, проверяем каждую страницу после рендеринга
При чёрно-белой печати смысл сохраняется, меню и кнопки не печатаются

## 9. Структура проекта и материалы

Один репозиторий и одно приложение
В опубликованном сайте все согласованные функции работают в браузере

| Путь | Содержимое |
| --- | --- |
| src/pages/ | Главная, обучение, практика, памятки, помощь и страница 404 |
| src/components/ | Общие кнопки, карточки, навигация и отображение блоков |
| src/features/learning/ | Прохождение уроков и тестов |
| src/features/practice/ | Общий игровой механизм для всех кейсов |
| src/features/resources/ | Поиск, фильтры и печать памяток |
| src/content/modules/ | Файлы модулей |
| src/content/lessons/ | Отдельные JSON-файлы уроков |
| src/content/scenarios/ | Отдельные JSON-файлы кейсов |
| src/content/resources/ | Отдельные JSON-файлы памяток |
| src/lib/ | Схемы данных, проверка связей, доступ к материалам и работа с прогрессом |
| src/styles/ | Тема, общие стили, стили компонентов и печати |
| public/images/ | Иллюстрации |
| public/pdf/ | Готовые PDF для печати |
| scripts/ | Проверка материалов и файлов перед сборкой |
| tests/ | Сквозные проверки пользовательских путей |
| docs/ | План, описание контента, инструкции и результаты проверок |

Файл src/styles/theme.css содержит общие цвета, размеры, отступы и скругления
Стили отдельных компонентов используют эти переменные
Уроки, тексты ответов и памятки не встраиваем внутрь React-компонентов
Материалы подключаем из src/content при сборке, отдельные запросы к API не нужны

| Тип материала | Основные данные |
| --- | --- |
| Module | id, slug, заголовок, порядок, аудитория, идентификаторы уроков |
| Lesson | id, slug, модуль, блоки содержания, вопросы, версия |
| Question и Choice | id, вопрос, варианты, правильный ответ и пояснения |
| Scenario | id, slug, участники, тема, первый шаг, версия, ссылки на памятки |
| Step и Option | id, история, варианты, последствия, следующий шаг, итоговые подсказки |
| Resource | id, slug, аудитория, тема, блоки, путь к PDF |

Это проектная структура данных, окончательные схемы фиксируем в репозитории при создании первого рабочего примера
Для модулей, уроков, кейсов и памяток задаём audience
Для детских материалов также задаём age_min=7 и age_max=10
Один материал может относиться к нескольким аудиториям
Детские и взрослые пояснения представлены отдельными блоками
Возраст и сведения о конкретном ребёнке не собираем

Содержание хранится структурированными блоками: абзац, список, таблица, схема и изображение
Текст схем выводится средствами верстки, сайт не выполняет произвольный HTML из материалов
У каждого материала стабильный идентификатор, у изменяемого урока или кейса также есть версия
Проверка перед сборкой выявляет неверную структуру JSON, повторяющиеся id и slug, отсутствующие ссылки и файлы
Для кейса проверяем существование первого шага, переходы, отсутствие циклов, достижимость всех шагов и завершение каждого пути
Допустимый финал обозначается явно, а не ссылкой на несуществующий шаг
Ошибка материала останавливает публикацию с указанием файла и причины

| Итоги | Разбор фактических выборов пользователя |
| Поиск и фильтры | Обработка небольшого набора памяток в браузере |
| Печать | Печатные CSS-стили и системный диалог браузера |
| Скачивание | Прямая ссылка на существующий PDF |
| Помощь | Статическая страница с согласованными контактами |
| Прогресс | Небольшая запись в localStorage |

Прогресс содержит версию схемы, идентификатор и версию материала, завершённые уроки, лучшие результаты тестов, текущий шаг и выборы
При завершении теста или кейса сохраняем итог, по которому можно показать отметку прохождения
Состояние React хранит текущую попытку, отдельный модуль отвечает за чтение и запись localStorage
Доступ к хранилищу и восстановление данных обрабатываем с проверкой структуры и ошибок

Прогресс сохраняется в том же браузере и профиле для того же адреса сайта
Перенос между устройствами, учётные записи и отчёт учителя по детям в первую версию не входят
На общем компьютере сохранённое прохождение может быть видно другому пользователю браузера
Есть кнопка "Сбросить мой прогресс" с подтверждением
При недоступном хранилище сайт работает в памяти и объясняет, что после закрытия результаты могут потеряться
При повреждённой записи или несовместимой версии материала предлагаем начать заново, остальные материалы продолжают работать
Очистка данных браузера удаляет прогресс, в приватном режиме он может не сохраниться после закрытия

Ответы учебных тестов доступны в файлах приложения
Это подходит для самостоятельного обучения, сайт не используется для защищённого экзамена
Личные сведения и свободный ввод ребёнка не сохраняем
Для ошибки загрузки приложения или файла предусматриваем понятное сообщение и возможность повторить действие
Неизвестный адрес и отсутствие материала показываем как понятную страницу 404
Опубликованные материалы доступны посетителям сайта, секреты в исходные данные не помещаем

## 11. Запуск, сборка и размещение

При реализации создаём и документируем следующие команды
Это требования к будущим npm-скриптам, их работоспособность проверяется после создания проекта

| Команда | Назначение |
| --- | --- |
| npm ci | Установка зависимостей по зафиксированному lock-файлу |
| npm run dev | Запуск разработки |
| npm run typecheck | Проверка типов TypeScript |
| npm run validate:content | Проверка материалов, переходов и наличия файлов |
| npm run test | Однократный запуск модульных и компонентных проверок |
| npm run test:e2e | Сквозные проверки |
| npm run build | Проверка типов и материалов, затем сборка в dist/ |
| npm run preview | Локальная проверка собранного сайта |

В README фиксируем поддерживаемую версию Node.js и порядок первого запуска
Конкретные совместимые версии зависимостей проверяем и фиксируем в начале реализации
npm run preview используем для локальной проверки сборки
Для публикации раздаём содержимое dist/ через HTTPS на статическом хостинге

Выбранный хостинг должен поддерживать возврат index.html для адресов приложения, таких как /practice/obshee-zadanie
При этом отсутствующие PDF и изображения должны возвращать ошибку файла, а не страницу приложения
Проверяем прямые ссылки и обновление вложенных страниц после публикации
Если выбранный хостинг не поддерживает нужные правила, сначала решаем вопрос маршрутизации
Настраиваем кэширование так, чтобы новая публикация не сохраняла у посетителя несовместимую старую страницу
Статический сайт можно разместить здесь через Sites по его поддерживаемому процессу публикации

Выпуск содержит согласованные материалы и рабочие функции, это полноценная первая версия по текущему объёму
Исходники, материалы и PDF сохраняем в Git, используем отдельные коммиты для законченных изменений
Для отката сохраняем сведения о рабочем выпуске и его исходном коммите
Результаты localStorage не являются серверной резервной копией и не восстанавливаются откатом сайта

## 13. Проверки приёмки

1) Главная > доступны переходы для учеников, родителей и учителей
2) Открытие прямой ссылки на урок > нужный материал отображается после обновления
3) Неизвестный адрес > понятная страница 404 с возвратом
4) Завершение урока > отметка сохраняется в этом браузере
5) Тест > по каждому выбранному ответу появляется содержательное пояснение
6) Запуск кейса > показаны участники, цель и первый шаг
7) Каждый вариант ответа > появляется соответствующее последствие
8) Повторное нажатие > один выбор не учитывается дважды
9) Переход далее > работает только после выбора и показа пояснения
10) Все пути каждого кейса > приводят к допустимому завершению
11) Обновление страницы > корректно восстанавливается текущий шаг
12) Обновлённая версия кейса > старое состояние не ломает игру
13) Итог > содержит фактические выборы и подходящую памятку
14) Повтор > начинается новая попытка
15) Подтверждённый сброс прогресса > локальные результаты удаляются
16) Недоступный localStorage > сайт работает с понятным ограничением
17) Фильтры и поиск > соответствуют аудитории и теме, пустой результат объяснён
18) Печать > на A4 нет меню, обрезанного текста и пустых декоративных страниц
19) PDF > скачивается существующий файл с читаемым русским текстом
20) Чёрно-белая печать > схемы остаются понятными
21) Клавиатура > доступны меню, ответы, фильтры и кнопки, фокус виден
22) Телефон и увеличение текста > нет наложений и потери основных действий
23) Ошибка загрузки файла > видны понятное сообщение и действие повтора
24) Ошибка структуры JSON или повторяющийся id > проверка указывает файл и блокирует сборку
25) Несуществующий переход, цикл или недостижимый шаг > проверка кейса завершается ошибкой
26) Изменение одного материала и новая сборка > сайт показывает исправленную версию без правок игрового компонента
27) Публикация из сохранённого коммита > воспроизводится рабочая версия сайта
28) Страница помощи > только согласованные контакты, нет неработающей формы
29) Вход "Детям" > видны материалы для 7–10 лет и понятные короткие подписи
30) Входы "Родителям" и "Учителям" > доступны соответствующие подборки и пояснения для взрослых
31) Детский кейс > один вопрос на экране, короткие варианты, пояснение без оценок личности
32) Кейс "Разные ожидания" > обозначен для взрослых и не включён в обязательный детский путь
33) Детский урок и памятка > соответствуют ограничениям по объёму, взрослые пояснения не мешают детскому прохождению
34) Повреждённые данные прогресса > можно начать заново, сайт не падает
35) Очистка данных сайта в браузере > сайт начинает новое прохождение
36) Отсутствующий PDF или рисунок > сборка отклонена, а на хостинге неизвестный файл не подменяется index.html
37) Проверка типов и сборка > завершаются без ошибок
38) Ключевой путь "главная > урок > кейс > памятка" > пройден целиком в опубликованной версии

Это будущие проверки, их прохождение сейчас не заявлено
Автоматизируем валидацию материалов, графы кейсов, сохранение состояния и ключевой пользовательский путь
Визуальное оформление, читаемость и печать проверяем отдельно

## 15. Возможное развитие: кабинет редактора

Этот раздел не входит в обязательный объём первой версии
Если учителю понадобится править материалы через браузер или появятся учётные записи и общий прогресс, отдельно проектируем серверную часть
Предпочтительный вариант для кабинета управления материалами: Django + SQLite
Django Admin можно настроить для внутренней работы редактора с материалами
Пользовательский интерфейс React можно сохранить, отдельно потребуется согласовать контракты данных и загрузку из серверной части

Переход включает модель данных, миграции, доступ редактора, серверную проверку, резервные копии и перенос материалов из файлов
Синхронизация результатов учащихся и сбор обращений являются отдельными задачами, их не добавляем автоматически вместе с кабинетом
SQLite рассматриваем для небольшого размещения с постоянным диском, достаточность оцениваем по фактическим требованиям
При росте требований выбор базы пересматриваем

Официальная опора по админке: https://docs.djangoproject.com/en/stable/ref/contrib/admin/
