# Как менять материалы и картинки

Сайт статический: материалы – JSON в `src/content`, изображения – `public/images`, PDF – `public/pdf`. Для изменения текста или картинки не нужно переписывать React-компоненты. После изменения нужна новая сборка и публикация. Админка не включена в эту итерацию.

## Заменить иллюстрацию

1. Добавьте файл в `public/images`, например `my-school.webp`. Используйте собственное изображение или изображение с разрешённым использованием. Для реальных фотографий детей заранее решите вопрос согласия и персональных данных.
2. В нужном JSON замените поле:

```json
"image": {
  "src": "/images/my-school.webp",
  "alt": "Два ученика обсуждают, как разделить работу над плакатом."
}
```

3. `src` – путь от корня сайта, без `public` и без внешнего адреса. `alt` описывает то, что изображено. Не помещайте учебный текст только внутрь картинки.
4. Выполните `npm run build`. Отсутствующее изображение остановит сборку с именем JSON-файла.
5. Проверьте страницу на телефоне и компьютере, затем сохраните изменения в Git и опубликуйте сборку.

Рекомендуемый формат – WebP, пропорции 3:2, ширина 1200–1600 px, размер около 100–250 КБ. Картинки не являются условием понимания урока: основной смысл остаётся в тексте. Если картинка не загружается, страница показывает объяснение; в материале доступен повтор загрузки.

Главная использует `/images/dialogue.webp`, объяснение медиации – `/images/classroom.webp`. Их подключение находится в `src/pages/Home.tsx` и `src/pages/Static.tsx`. Остальные материалы управляются полем `image` в JSON.

## Добавить материал

Скопируйте близкий по типу JSON в ту же папку. Задайте уникальные `id` и `slug`; имя файла должно совпадать со `slug`. Укажите `audience`: `children`, `parents`, `teachers`. Эти метки описывают роли в содержании и используются для контекстных пояснений, но не фильтруют доступ к материалам. Возрастные поля не используются. Все материалы отображаются в общих каталогах.

- Урок включается в `lessons` соответствующего модуля; в уроке поле `module` указывает на тот же модуль. В каждом модуле два урока и три вопроса. Урок показывает по одному короткому блоку на экран. Тексты объяснений и ответов лежат в JSON.
- У каждого кейса три реплики на шаг, четыре сюжетных шага, последствия и пояснения. `first_step_id` указывает на существующий шаг, каждый `next_step_id` – на следующий шаг или `null` для финала. Циклы и недостижимые шаги запрещены.
- У памятки четыре–шесть действий, пример реплики, чеклист и путь к настоящему PDF. Все данные отображаются как текст, произвольный HTML не выполняется.

При изменении смысла или переходов кейса увеличьте `version`: устаревшая попытка будет безопасно начата заново, другие кейсы останутся сохранены. Увеличьте версию урока, если требуется повторное прохождение после содержательной правки.

После правок: `npm run validate:content`, `npm test`, `npm run build`, `npm run test:e2e`. Для обновления PDF сначала `python scripts/generate-pdf.py`, затем визуальная проверка печати и PDF. Генератор читает все JSON памяток.

## Что потребуется для админки

Чтобы редактировать материалы в браузере и публиковать их для всех посетителей, понадобится отдельно выбрать хранение, вход редактора и процесс публикации. План допускает Django Admin; для текущего статического хостинга возможен редактор с сохранением в Git. Загрузка файла только в localStorage не обновит сайт у других людей и не заменяет админку.


## Страница о медиации и подробные уроки

`src/content/pages/mediation.json` управляет текстом на главной и странице `/mediation`. Таблицы, роли и шаги встречи имеют отдельные поля и проверяются перед сборкой. Иллюстрации из нового документа: `/images/mediation-meeting.webp` и `/images/conflict-ball.webp`.

У урока может быть массив `sections` с `title` и `details`. Число элементов должно совпадать с массивом коротких `blocks`: краткая мысль видна сразу, полный текст открывается через «Разобраться подробнее». Оглавление позволяет выбрать тему. При содержательной правке увеличьте `version` урока. Для обновлённых вопросов модуля также увеличьте `version` модуля, чтобы прежний результат не засчитывался за новую проверку.

Шрифт интерфейса задаётся в `src/styles/theme.css`, локальный Manrope и лицензия находятся в `public/fonts/`. Генератор PDF использует `Manrope-Regular.ttf` из той же папки. Квадраты чеклиста рисуются как векторные фигуры, так как в Manrope нет соответствующего глифа.
